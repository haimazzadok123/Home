# מטיילים עם דוד חיים

אפליקציית תכנון מסלולי טיול: בוחרים נקודת יציאה ונקודת יעד, מקבלים מסלול נסיעה על גבי מפה,
ולאורך המסלול מוצגות נקודות תצפייה נופיות, מקומות אוכל כשר, תחנות דלק, ואתרי לינה של קק"ל /
רשות הטבע (מסננים כל קטגוריה בנפרד, וניתן לשלוט על רוחב "המסדרון" של החיפוש סביב המסלול).
אפשר גם לשמור מסלולים מועדפים ולשתף מסלול בקישור.

## טכנולוגיה

פרויקט React + TypeScript + Vite, ללא שרת משלו — כל הנתונים מגיעים משירותי OpenStreetMap
חינמיים וללא צורך במפתח API:

- **חיפוש מקומות (geocoding):** [Nominatim](https://nominatim.org/)
- **תכנון מסלול נסיעה:** [OSRM](https://project-osrm.org/) (שרת הדגמה ציבורי)
- **נקודות עניין (תצפיות / אוכל כשר / תחנות דלק / לינה):** [Overpass API](https://overpass-api.de/) על נתוני OpenStreetMap
- **מפה:** [Leaflet](https://leafletjs.com/) עם אריחי OpenStreetMap
- **חישובי מרחק מהמסלול:** [Turf.js](https://turfjs.org/)
- **מסלולים שמורים:** `localStorage` בדפדפן — נשמר רק על המכשיר/דפדפן שבו שמרו, לא מסתנכרן בין מכשירים
- **שיתוף מסלול:** קידוד המסלול והסינונים בפרמטרים של כתובת ה-URL; פתיחת הקישור משחזרת את אותו מסלול

## הרצה מקומית

```bash
npm install
npm run dev
```

פקודות נוספות: `npm run build` לבנייה לפרודקשן, `npm run lint` להרצת בודק הסגנון.

## איך זה עובד

1. מחפשים נקודת יציאה ונקודת יעד (חיפוש חופשי, מבוסס Nominatim).
2. לוחצים "תכנון מסלול" — מתקבל מסלול נסיעה מ-OSRM ומצויר על המפה.
3. האפליקציה בונה תיבת חיפוש (bounding box) סביב המסלול ברוחב שנבחר (1–20 ק"מ), ושואלת את
   Overpass על נקודות תצפייה (`tourism=viewpoint`), מקומות עם תיוג כשרות
   (`diet:kosher=yes`, `cuisine=kosher`, `shop=kosher`), תחנות דלק (`amenity=fuel`), ואתרי
   קמפינג (`tourism=camp_site`) שמופעלים ע"י קק"ל או רשות הטבע והגנים (לפי תגית operator/name).
4. לכל נקודת עניין מחושב המרחק מהמסלול ומיקומה לאורכו, כדי למיין ולסנן אותה.
5. "שמור מסלול" שומר את נקודות המסלול, רוחב החיפוש והסינונים הנוכחיים ב-`localStorage`;
   "שיתוף" בונה קישור עם אותם נתונים בפרמטרים של ה-URL (או פותח את תפריט השיתוף המובנה
   בנייד, אם קיים).
6. תכנון מסלול חדש תמיד מנקה קודם את נתוני המסלול הקודם (מסלול, נקודות עניין, סיכום),
   כדי שלא יישארו נתונים ישנים על המפה אם השלב הבא (איתור נקודות עניין) נכשל. כפתור
   "🗑️ נקה" ליד "תכנון מסלול" מאפשר לאפס את הטופס והמפה בכל שלב.

## מגבלות ידועות

- תיוג כשרות ב-OpenStreetMap חלקי — לא כל מקום כשר בהכרח מתויג ככזה, אז חלק מהמקומות עלולים
  לא להופיע.
- סינון המשנה לאוכל כשר (בשרי/חלבי) מבוסס על ניחוש מתגיות לא סטנדרטיות ומילות מפתח בשם/סוג
  המטבח, ולכן עוד פחות אמין מתיוג הכשרות עצמו — חלק מהמקומות לא יסווגו נכון. סינון סוג המקום
  (מסעדה/מזון מהיר) מבוסס על תגית `amenity` הסטנדרטית ולכן אמין יותר.
- סינון המשנה לתחנות דלק: חנות נוחות מבוסס על תגית OSM סבירה למדי. שטיפת רכב מבוסס על תגית
  `car_wash` וגם על מילות מפתח בשם/מותג ("שטיפה"/"car wash"), אבל עדיין תלוי בתיוג ידני —
  חלק מהתחנות עם שירות שטיפה בפועל פשוט לא יופיעו. "סגורה בשבת" מנוחש משעות הפעילות
  (`opening_hours`) — לא תגית אמיתית, ולכן מפספס יותר ממה שהוא תופס נכון. הסרנו את סינון
  "מקבלת דלקן" — אין לזה שום תגית ב-OSM (קונספט מקומי ישראלי), כך שהסינון היה כמעט תמיד ריק.
- שרתי ה-API הציבוריים (Nominatim / OSRM / Overpass) מוגבלים בקצב הבקשות ומיועדים לשימוש
  קליל; לשימוש כבד/מסחרי כדאי לעבור לשירותים בתשלום או לארח מופע עצמאי.
- תכנון המסלול הוא לנסיעה ברכב בלבד (`driving` profile ב-OSRM).
- אתרי הלינה מוגבלים לקק"ל/רשות הטבע לפי מילות מפתח בתגית `operator` (או `name` כגיבוי) —
  אין תגית OSM ייעודית ל"שייך לקק"ל/לרשות הטבע", אז אתר שלא תייג את המפעיל שלו בעברית/אנגלית
  מוכרת פשוט לא יופיע, גם אם בפועל הוא כן שייך לאחד מהגופים האלה.
