# מטיילים עם דוד חיים

אפליקציית תכנון מסלולי טיול: בוחרים נקודת יציאה ונקודת יעד, מקבלים מסלול נסיעה על גבי מפה,
ולאורך המסלול מוצגות נקודות תצפייה נופיות, מקומות אוכל כשר, תחנות דלק, אתרי לינה של קק"ל /
רשות הטבע, ואתרי טיולים ממפת ישראל (מסננים כל קטגוריה בנפרד, וניתן לשלוט על רוחב "המסדרון"
של החיפוש סביב המסלול).
אפשר גם לשמור מסלולים מועדפים ולשתף מסלול בקישור.

## טכנולוגיה

פרויקט React + TypeScript + Vite, ללא שרת משלו — כל הנתונים מגיעים משירותי OpenStreetMap
חינמיים וללא צורך במפתח API:

- **חיפוש מקומות (geocoding):** [Nominatim](https://nominatim.org/)
- **תכנון מסלול נסיעה:** [OSRM](https://project-osrm.org/) (שרת הדגמה ציבורי, ושרת FOSSGIS כגיבוי)
- **נקודות עניין (תצפיות / אוכל כשר / תחנות דלק / לינה):** [Overpass API](https://overpass-api.de/) על נתוני OpenStreetMap
- **אתרי טיולים:** [Israel Hiking Map](https://israelhiking.osm.org.il/) (מבוסס OpenStreetMap וקהילת הטיולים בישראל)
- **מפה:** [Leaflet](https://leafletjs.com/) עם אריחי OpenStreetMap
- **חישובי מרחק מהמסלול:** [Turf.js](https://turfjs.org/)
- **מסלולים שמורים:** `localStorage` בדפדפן — נשמר רק על המכשיר/דפדפן שבו שמרו, לא מסתנכרן בין מכשירים
- **שיתוף מסלול:** קידוד המסלול והסינונים בפרמטרים של כתובת ה-URL; פתיחת הקישור משחזרת את אותו מסלול

## פרטיות, תנאים ונגישות

- באתר יש מדיניות פרטיות, תנאי שימוש והצהרת נגישות (`src/components/LegalPages.tsx`), שנפתחים
  מהקישורים בתחתית הפאנל או ישירות דרך `#privacy`, `#terms`, `#accessibility`.
- פרטי הקשר בעמודים נקבעים בקבוע `CONTACT_EMAIL` באותו קובץ (כרגע ריק, ומוצגת הודעה שיפורסמו בקרוב).
- הגופנים נארזים עם האתר (`@fontsource`), כך שלא נשלח מידע לשירות גופנים חיצוני.
- מדיניות אבטחת תוכן (CSP) ב-`index.html` מתירה פנייה רק לשירותים שמפורטים במדיניות הפרטיות. כשמוסיפים
  שירות חדש, צריך להוסיף אותו גם ל-CSP וגם לטבלה במדיניות הפרטיות.

## הרצה מקומית

```bash
npm install
npm run dev
```

פקודות נוספות: `npm run build` לבנייה לפרודקשן, `npm run lint` להרצת בודק הסגנון.

## איך זה עובד

1. מחפשים נקודת יציאה ונקודת יעד (חיפוש חופשי, מבוסס Nominatim).
2. לוחצים "תכנון מסלול" — מתקבל מסלול נסיעה מ-OSRM ומצויר על המפה.
3. בוחרים מה לחפש בדרך (תצפיות / אוכל כשר / תחנות דלק / לינה). האפליקציה מחפשת רק את הסוגים
   שנבחרו, ובחירת סוג נוסף אחרי שהמסלול מוכן מחפשת רק אותו. החיפוש ב-Overpass נעשה לאורך קו
   המסלול (`around:` על גרסה מפושטת שלו) ברוחב שנבחר (1–20 ק"מ): נקודות תצפייה
   (`tourism=viewpoint`), מקומות עם תיוג כשרות (`diet:kosher=yes`, `cuisine=kosher`,
   `shop=kosher`), תחנות דלק (`amenity=fuel`), ואתרי קמפינג (`tourism=camp_site`) שמופעלים ע"י
   קק"ל או רשות הטבע והגנים (לפי תגית operator/name). כשבוחרים תצפיות, האפליקציה גם דוגמת נקודות
   לאורך המסלול (עד 10 נקודות, כל כ-20 ק"מ) ושואלת את Israel Hiking Map על האתר הקרוב לכל נקודה.
   כל חיפוש אפשר לבטל, ולכל שרת יש שרת גיבוי וזמן המתנה מוגבל.
4. לכל נקודת עניין מחושב המרחק מהמסלול ומיקומה לאורכו, כדי למיין ולסנן אותה.
5. "שמור מסלול" שומר את נקודות המסלול, רוחב החיפוש והסינונים הנוכחיים ב-`localStorage`;
   "שיתוף" בונה קישור עם אותם נתונים בפרמטרים של ה-URL (או פותח את תפריט השיתוף המובנה
   בנייד, אם קיים).
6. תכנון מסלול חדש תמיד מנקה קודם את נתוני המסלול הקודם (מסלול, נקודות עניין, סיכום),
   כדי שלא יישארו נתונים ישנים על המפה אם השלב הבא (איתור נקודות עניין) נכשל. כפתור
   "🗑️ נקה" ליד "תכנון מסלול" מאפשר לאפס את הטופס והמפה בכל שלב.

## מגבלות ידועות

- תיוג כשרות ב-OpenStreetMap חלקי — לא כל מקום כשר בהכרח מתויג ככזה, אז חלק מהמקומות עלולים
  לא להופיע.
- סינון המשנה לאוכל כשר (בשרי/חלבי) מבוסס על ניחוש מתגיות לא סטנדרטיות ומילות מפתח בשם/סוג
  המטבח, ולכן עוד פחות אמין מתיוג הכשרות עצמו — חלק מהמקומות לא יסווגו נכון. סינון סוג המקום
  (מסעדה/מזון מהיר) מבוסס על תגית `amenity` הסטנדרטית ולכן אמין יותר.
- סינון המשנה לתחנות דלק: חנות נוחות מבוסס על תגית OSM סבירה למדי. שטיפת רכב מבוסס על תגית
  `car_wash` וגם על מילות מפתח בשם/מותג ("שטיפה"/"car wash"), אבל עדיין תלוי בתיוג ידני —
  חלק מהתחנות עם שירות שטיפה בפועל פשוט לא יופיעו. "סגורה בשבת" מנוחש משעות הפעילות
  (`opening_hours`) — לא תגית אמיתית, ולכן מפספס יותר ממה שהוא תופס נכון. הסרנו את סינון
  "מקבלת דלקן" — אין לזה שום תגית ב-OSM (קונספט מקומי ישראלי), כך שהסינון היה כמעט תמיד ריק.
- שרתי ה-API הציבוריים (Nominatim / OSRM / Overpass) מוגבלים בקצב הבקשות ומיועדים לשימוש
  קליל; לשימוש כבד/מסחרי כדאי לעבור לשירותים בתשלום או לארח מופע עצמאי.
- תכנון המסלול הוא לנסיעה ברכב בלבד (`driving` profile ב-OSRM).
- אתרי הלינה מוגבלים לקק"ל/רשות הטבע לפי מילות מפתח בתגית `operator` (או `name` כגיבוי) —
  אין תגית OSM ייעודית ל"שייך לקק"ל/לרשות הטבע", אז אתר שלא תייג את המפעיל שלו בעברית/אנגלית
  מוכרת פשוט לא יופיע, גם אם בפועל הוא כן שייך לאחד מהגופים האלה.
- אתרי הטיולים (Israel Hiking Map) מבוססים על דגימת נקודות בודדות לאורך המסלול ולא על חיפוש
  אמיתי בכל שטח המסדרון (ה-API הציבורי שלהם לא תומך בזה) — הכיסוי דליל, אותו אתר עלול לחזור
  על עצמו בכמה דגימות סמוכות, וקטע מסלול בין שתי דגימות עלול לפספס אתרים קרובים אליו. זהו
  מקור נתונים משלים ולא חיפוש ממצה כמו שאר הקטגוריות.

## לוח הבית (`public/dashboard/`)

דף עצמאי (HTML + CSS + JS, בלי שלב בנייה) שמיועד לעמוד פתוח על אייפד או על אייפון במצב שוכב:
שעון עם יום ותאריך (לועזי ועברי), מזג אוויר, חדשות, מבזקים (ynet) וספורט בשלושה טאבים, מניות ושערי מטבע, מצב החיבור
לרשת, זמני שבת, ותפריט צד עם קישורים לשאר האתרים. כתובת: `/Home/dashboard/`.

- **התקנה במכשיר:** ב-Safari ‏← שיתוף ← "הוסף למסך הבית". הדף נפתח במסך מלא ומשאיר את המסך דולק
  (אפשר לכבות בהגדרות). באייפון שוכב התצוגה עוברת לשני לוחות במסך עם החלקה הצידה. זה לא ה-StandBy
  של iOS עצמו — Apple מאפשרת שם רק ווידג'טים של אפליקציות, לא דפי אינטרנט.
- **מקורות הנתונים:** מזג אוויר ואיכות אוויר מ-Open-Meteo, זמני שבת מ-Hebcal, שערי מטבע מ-Frankfurter
  (שערים יומיים), כותרות מ-RSS של ynet, mako, וואלה, ישראל היום, הארץ, מעריב וגלובס (בוחרים אילו בהגדרות; החדשים נקראים דרך rss2json, שמחזיר עד 10 כותרות לאתר ומתעדכן בערך פעם בשעה). ערוץ 7 נקרא ישירות. המבזקים (ynet, מעריב, ופורום הסקופים של רוטר) מתרעננים כל דקה וחצי; רוטר מקודד ב-windows-1255 ולכן הפיד מפוענח לפי ההצהרה שב-XML. לגבי השניים הראשונים: ynet ו-mako (mako נקרא ישירות; ynet דרך allorigins או rss2json, כי
  האתר לא מאפשר קריאה ישירה מדפדפן), בדיקת מהירות מול `speed.cloudflare.com`.
- **ספורט:** ONE נקרא ישירות מה-RSS שלו (`one.co.il/rss`), כתבות ספורט 5 מגיעות מהפיד של mako (לספורט 5
  אין פיד משלו), ובנוסף ynet ספורט.
- **רדיו:** גלגלצ, גל"צ, כאן ב / גימל / 88, ‏103FM, רדיוס 100 וקול ברמה, מהשידור הרשמי של כל תחנה. יש כפתור
  עצירה ומחוון עוצמה; באייפון ובאייפד המחוון מוסתר כי שם העוצמה נשלטת רק מכפתורי המכשיר.
- **תנאי שימוש:** נפתחים מתפריט הצד, כולל רשימת מקורות המידע והרישיונות שלהם.
- **מניות:** דורשות מפתח חינמי של [Finnhub](https://finnhub.io/register) שמזינים בהגדרות (נשמר ב-`localStorage`
  במכשיר בלבד). בלי מפתח הדף מנסה מקור פתוח, שלא תמיד זמין. ליד שער הדולר מוצג גם S&P 500 (עם מפתח Finnhub: דרך קרן הסל SPY).
- **רשת:** דף אינטרנט לא יכול לקרוא את שם רשת ה-Wi-Fi או את עוצמת האות, ולכן הכרטיס מודד בעצמו זמן
  תגובה, מהירות הורדה ומהירות העלאה. ל-Speedtest אין ממשק שדף אחר יכול להפעיל, אז יש רק קישור שפותח את האתר שלהם. בדיקת המהירות האוטומטית (כל חצי שעה) מורידה עד כ-15MB ומעלה עד כ-8MB בכל פעם.
- **מסכי מחשב:** הפריסה מתוכננת סביב טאבלט. במחשב `fitToWindow()` שב-`app.js` מודד את החלון בפועל (בלי סרגלי הדפדפן ושורת המשימות, ואחרי הגדלת התצוגה של Windows) ומגדיל את כל הדף ביחס אחיד דרך המשתנה `--z`. הרוחב מוגבל, כך שרק במסכים רחבים מאוד (21:9) הרקע נראה בצדדים. `style.css` ו-`app.js` נטענים עם `?v=` כדי שדפדפן לא יציג גרסה ישנה.
- **גרף זמן התגובה:** [Liveline](https://github.com/benjitaylor/liveline) של Benji Taylor (MIT). זו ספריית React, ולכן היא נארזת יחד עם React לקובץ אחד, `public/dashboard/vendor/liveline.js`, שנשמר במאגר. אחרי שינוי ב-`dashboard-src/liveline-entry.js` או עדכון הספרייה מריצים `npm run build:dashboard`. אם הקובץ לא נטען, הכרטיס חוזר לקו ה-SVG הפשוט.
- **אייקונים:** [Kubai Icons](https://icons.kubai.design/) (`kubai-icons`, MIT) למזג האוויר, לכותרות הכרטיסים, לתפריט ולכפתורים. רק האייקונים שבשימוש נארזים ל-`public/dashboard/vendor/kubai.js` (מ-`dashboard-src/kubai-entry.js`, באותה פקודה `npm run build:dashboard`). האייקונים משתמשים במאפייני `style` בתוך ה-SVG, ולכן ה-CSP מתיר `'unsafe-inline'` לסגנונות בלבד. אם הקובץ לא נטען, מזג האוויר חוזר לאימוג'י והכפתורים לאייקונים הפשוטים.
- **עדכון אוטומטי:** כל 5 דקות הדף בודק את `version.json`, ואם המספר שם שונה מה-`?v=` שבו נטען `app.js`, הוא נטען מחדש. הוא מחכה כשהרדיו מנגן או כשחלון פתוח, ונטען מחדש לכל היותר פעם אחת לכל גרסה. **בכל שינוי בדשבורד מעלים את המספר בשלושה מקומות: שני ה-`?v=` ב-`index.html` וב-`version.json`.**
- **מסך מתקפל פתוח וטאבלט עומד:** הכול במסך אחד בלי גלילה (שלוש עמודות בשוכב, שתיים בעומד); במסכים קטנים מ-iPad הדף מוקטן בעזרת אותו `--z`. המידות של אייפון מתקפל הן הערכה (כ-904×640 נקודות) ולא נבדקו על מכשיר.
- כשמוסיפים מקור נתונים או תחנת רדיו צריך להוסיף אותם גם ל-CSP שב-`index.html` וגם לרשימת המקורות בתנאי השימוש.
